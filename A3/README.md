## 1. Introduction
In the construction industry, collaboration is essential. Architects, engineers, and BIM professionals work together, sharing information, files, and knowledge throughout a project.

However, as projects become more digital, the way we work together is also changing. It is no longer just about sharing files, but also about understanding how information develops, learning from others, and building on previous work. OpenBIM supports collaboration by allowing different disciplines and software to exchange information through open standards such as IFC. But how do we organize the knowledge, tools, and workflows that support this collaboration? This is where GitHub becomes relevant. GitHub is more than a place to store files. It provides a way for people to collaborate, share knowledge, track progress, and learn from each other's work. This tutorial explores how GitHub can support OpenBIM, how it influences the way we work and think, and how its basic functions can be used in practice.

## 1. Problem Statement
During the Advanced OpenBIM course, our fellow students work with different digital resources, including IFC models, Python scripts, and project documentation. Managing and sharing these resources between group members can make collaboration challenging.

When files are stored separately or shared through different platforms, it can be difficult to track changes, identify the latest versions, and access previous work. This can lead to duplicated work, misunderstandings, and inefficient knowledge sharing.

These challenges highlight the need for a more structured approach to collaboration in OpenBIM projects.

GitHub offers a possible solution by providing a shared platform where students can organize files, track changes, and share knowledge. This supports more transparent workflows and encourages students to learn from and build upon each other's work.

## How GitHub Supports OpenBIM Collaboration
GitHub helps students organize their work, share documents and knowledge as well as follow changes throughout a project. Instead of working on one document having to send it through, team members can contribute to the same project and learn from each other's work.

In OpenBIM, this is especially useful when working with Python scripts, IFC-related tools, and project documentation. GitHub allows students to share these resources, understand how they have developed, and improve existing work instead of starting from the beginning.

By making work more accessible, GitHub encourages a more collaborative way of working, where knowledge is shared and projects can be continuously improved.

## What Is GitHub?
GitHub is an online platform from microsoft where people can store, organize, share, and collaborate on digital projects. It works similarly to Google Drive, but includes additional features for tracking changes and managing shared projects between students.

GitHub uses Git, a version control system that records changes to files. This allows users to follow a project changes and access previous versions.

In OpenBIM, GitHub is especially useful for sharing Python scripts, documentation, and other digital resources.

## Tutorial: How to Use GitHub
The following tutorial introduces the basic functions of GitHub and demonstrates how they can be used in an OpenBIM project.

### Step 1: Create a GitHub Account
To get started, visit the GitHUB website and make an account. Follow the instructions to create an account. Once your account is created, log in to GitHub.

### Step 2: Create a Repository
A repository is a place where you can store and organize your project files.

To create one, click the + icon in the top right corner and select New repository. Give your repository a name, such as OPENBIM-project. Select Public to make the repository accessible to others, and choose Add a README file. Finally, click Create repository.

### Step 3: Understand the README Markdown File
A README.md is a file that explains what a project is about and what it contains. It is usually the first thing people see when opening a GitHub repository.

The .md stands for Markdown, a simple way of formatting text using symbols.

For example, a README for an OpenBIM project could look like this:

```markdown
# My OpenBIM Project

## Project Description
This project explores how GitHub supports
collaboration and knowledge sharing in OpenBIM.

## Project Files
- Python scripts
- IFC examples
- Documentation

## Authors
Advanced OpenBIM students
```

In Markdown, a hashtag creates a main heading, two hashtags create a smaller heading, and a - creates bullet points.

GitHub automatically displays Markdown as a formatted document, making project information easier to read and understand.

To edit your README, open the readme.md file in your repository and click the pencil icon. Make your changes and select Commit changes to save them.

### Step 4: Upload and Save Files
To upload files, open your repository and select add file, followed by upload files.

Choose a file from your computer and click commit changes to save it to the repository.

A commit records changes made to a project, allowing users to track its development and access previous versions.

### Step 5: Share and Collaborate
To share your repository, you have to copy its URL and send it to another person. If the repository is public, anyone with the link can view its contents.

This allows multiple people to work on the same project, share knowledge with each other.

## 8. Learning from BIM at Different Levels
GitHub can help people share knowledge and learn from each other at different levels. On a personal level, students can learn from their own work and mistakes. In teams, GitHub makes it easier to share ideas, work together, and improve projects. At an institutional level, universities can share tutorials and resources that future students can use.

This allows knowledge to be shared and reused instead of starting from the beginning every time.

## 9. Conclusion
GitHub is a useful tool for collaboration in OpenBIM. It helps people organize files, keep track of changes, and share knowledge.

It also makes it easier for students and teams to learn from each other and improve their work.
